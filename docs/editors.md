# Редакторы и подсказки

SDK написан так, чтобы редактор помогал на каждом шагу: подсказывает методы и их
аргументы, показывает описание при наведении, ловит опечатки в значениях и неверные
типы ещё до запуска. Эта страница объясняет, что для этого сделано и как включить
подсказки в **PyCharm**, **VS Code** и других редакторах.

## Что SDK даёт редактору

| Что | Как это помогает |
|---|---|
| **Типы везде** | У всех публичных функций, методов и атрибутов есть аннотации типов. Редактор подсказывает аргументы и результат (`await self.api.gold()` — это `int`). |
| **Маркер `py.typed`** | Пакет помечен как типизированный (PEP 561). Анализаторы типов (mypy, pyright, PyCharm) используют его аннотации, а не считают пакет «чёрным ящиком». |
| **Описание на русском** | У каждого класса, метода, функции и поля модели есть описание. Оно показывается при наведении и в окне быстрой документации. |
| **Формат описаний** | Описания оформлены полями reStructuredText: `:param имя:`, `:returns:`, `:raises Исключение:`. Их понимают PyCharm (формат по умолчанию) и Pylance. |
| **Литералы** | `Reaction`, `GoldBar`, `Facing`, `ModerationAction` — списки допустимых строк. Редактор предлагает их при вводе, а анализатор ловит опечатку. |
| **Описания полей моделей** | У полей `User`, `Position`, `ChatEvent` и остальных есть описание: наведите курсор на `user.username`. |
| **`__all__`** | Пакет явно перечисляет, что экспортирует, поэтому автодополнение `from sukarisebot import …` показывает только нужное. |
| **Строгая проверка** | Сам SDK проходит `mypy --strict` и `pyright` в режиме `strict`: типы не «просачиваются» в ваш код как `Any`. |

## PyCharm

1. **Интерпретатор.** Нужен Python 3.13 или новее. Откройте **Settings → Project →
   Python Interpreter** и убедитесь, что выбрано окружение, в которое установлен SDK
   (`pip install -e .`). Если PyCharm подчёркивает `import sukarisebot` как
   неразрешённый, выбран не тот интерпретатор.
2. **Версия PyCharm.** SDK использует синтаксис Python 3.12 и новее: инструкцию `type X = …`
   и параметры типов в функциях (`async def wait_for[E: Event](…)`). Современные версии
   PyCharm (**2024.1 и новее**) его понимают. В очень старых версиях такие места могут
   подсвечиваться как ошибки, хотя код работает.
3. **Подсказки при вводе.**
   - Начните писать `self.api.` — PyCharm покажет все действия бота.
   - **Quick Documentation** — описание метода или поля: `Ctrl+Q` (Windows и Linux),
     `F1` (macOS) или просто задержите курсор.
   - **Parameter Info** — параметры вызова: `Ctrl+P` внутри скобок.
   - **Go to Declaration** — перейти к определению: `Ctrl+B`.
4. **Переопределение обработчиков.** Чтобы не набирать сигнатуру обработчика вручную,
   в теле класса бота нажмите **Code → Override Methods…** (`Ctrl+O`), выберите
   `on_chat`, `on_user_join` и другие — PyCharm сгенерирует метод с правильной
   сигнатурой и типами.
5. **Формат описаний.** Описания в SDK оформлены в стиле reStructuredText, который в
   PyCharm включён по умолчанию (**Settings → Tools → Python Integrated Tools → Docstrings →
   Docstring format → reStructuredText**). Если вы переключили формат, верните его, чтобы
   `:param:`, `:returns:` и `:raises:` отображались красиво.
6. **Проверка типов.** Встроенные инспекции PyCharm находят многие ошибки сразу.
   Для полной строгой проверки добавьте внешний инструмент: плагин **Mypy** или запуск
   `mypy` из терминала (см. ниже).
7. **Работа из клонированного репозитория.** Если вы редактируете сам SDK, отметьте
   каталог `src` как **Sources Root** (правый щелчок → *Mark Directory as → Sources
   Root*).

## Visual Studio Code

1. Установите расширение **Python** (оно подтягивает **Pylance**) и выберите
   интерпретатор Python 3.13 (`Ctrl+Shift+P` → *Python: Select Interpreter*), в
   который установлен SDK.
2. Подсказки работают из коробки: наведите курсор на метод, чтобы увидеть описание;
   `Ctrl+Shift+Space` внутри скобок показывает параметры.
3. Чтобы получать предупреждения о типах, включите проверку в настройках
   (`settings.json`):

   ```json
   {
     "python.analysis.typeCheckingMode": "strict"
   }
   ```

   По умолчанию Pylance почти не показывает предупреждений о типах (`off`); `basic` — разумное
   начало, `strict` — самый строгий режим, как у самого SDK.
   (Если в каталоге есть `pyproject.toml` с секцией `[tool.pyright]`, настройки берутся
   оттуда.)

## Другие редакторы

Neovim, Helix, Sublime Text, Emacs, Zed и другие общаются с языковыми серверами по
протоколу LSP. Достаточно подключить сервер, понимающий типы Python:

- **pyright** или **basedpyright** — тот же движок, что в Pylance;
- **pylsp** с плагином `pylsp-mypy` — на основе mypy;
- **jedi-language-server** — подсказки без строгой проверки типов.

SDK работает со всеми: описания читаются из исходного кода, а типы — из аннотаций и
файла `py.typed`.

## Проверка типов из командной строки

В `pyproject.toml` SDK уже настроены обе проверки. Запускайте их из корня репозитория:

```bash
python -m mypy          # режим strict, см. [tool.mypy]
python -m pyright       # режим strict, см. [tool.pyright]
```

Проверять код **своего бота** с теми же строгими правилами можно, добавив в его
`pyproject.toml`:

```toml
[tool.mypy]
strict = true

[tool.pyright]
typeCheckingMode = "strict"
```

## Что подсказывают типы: примеры

```python
from sukarisebot import Bot, Position, User


class Demo(Bot):
    async def on_chat(self, user: User, message: str) -> None:
        await self.api.react("hart", user.id)          # ← ошибка: допустимы clap, heart, thumbs, wave, wink
        await self.api.move_to(Position(1.0, 0.0))     # ← ошибка: не хватает аргумента z
        gold: str = await self.api.gold()              # ← ошибка: gold() возвращает int
```

Анализатор типов находит эти ошибки до запуска. Если бы вы всё же запустили код, SDK
поймал бы их при выполнении: `InvalidArgument` с понятным текстом.

### Совет: `match` по событиям и положениям

`Location` и `Event` — объединения. Разбирайте их через `match`; анализатор проверит, что
вы учли все варианты:

```python
from sukarisebot import AnchorPosition, Location, Position


def describe(location: Location) -> str:
    match location:
        case Position(x=x, z=z):
            return f"на полу ({x:.1f}, {z:.1f})"
        case AnchorPosition(entity_id=furniture):
            return f"на мебели {furniture}"
```

### Совет: данные в `state` и `user_state`

`self.state` и `self.user_state(id)` — словари `dict[str, object]`, то есть значения имеют
тип `object`. Прежде чем использовать значение, сузьте тип проверкой:

```python
from sukarisebot import Bot


class Counter(Bot):
    def bump(self) -> int:
        value = self.state.get("count", 0)
        count = (value if isinstance(value, int) else 0) + 1
        self.state["count"] = count
        return count
```

## Если подсказок нет

| Симптом | Возможная причина и решение |
|---|---|
| `import sukarisebot` подчёркнут как неразрешённый | В редакторе выбран другой интерпретатор, чем тот, куда установлен SDK. Выберите нужный или выполните `pip install -e .` в текущем окружении. |
| Автодополнение не показывает методы `self.api.` | Редактор не вывел тип `self.api`. Убедитесь, что класс наследует `Bot` и интерпретатор выбран верно. |
| Описания не отображаются | Установите SDK именно как пакет (`pip install -e .`), а не копированием файлов, чтобы рядом лежал `py.typed`. В PyCharm проверьте формат описаний (reStructuredText). |
| Подсветка ошибок на `type X = …` и `def f[T]()` | Редактор старше синтаксиса Python 3.12. Обновите редактор. |
| `reportPrivateUsage` или подобное в своём боте | Не обращайтесь к членам с подчёркиванием (`bot._engine` и т. п.): это внутреннее устройство, которое может измениться. |

# Частые вопросы

## Бот подключился, но не реагирует на сообщения

Проверьте по порядку:

1. **Есть ли обработчик или команда.** Бот слышит только то, для чего переопределён
   обработчик (`on_chat`, `on_user_join` …) или объявлена команда. См.
   [«Обработчики»](handlers.md).
2. **Команды начинаются с `!`.** `!roll` — команда, `roll` — нет.
3. **Команда только для владельца** (`owner_only=True`) отвечает отказом всем, кроме владельца
   *комнаты*.
4. **Бот действительно в комнате.** Он должен появиться в списке людей под именем, которое вы ему дали.
   Если нет, включите журнал (`logging.basicConfig(level=logging.INFO)`) и ищите причину
   в [таблице отказов](errors.md#отказы-при-подключении).
5. **Ошибка в вашем коде.** Исключения не роняют бота, а уходят в `on_error` и в журнал
   `sukarisebot` — включите журнал, чтобы их увидеть.

## `bot.room` не обновляется: ушедшие остаются, новые не появляются

Состав комнаты обновляют события входа, выхода и перемещения, а они приходят, только
если переопределены `on_user_join`, `on_user_leave` и `on_user_move` (тела могут быть пустыми).
Подробнее — [«Инструменты»](tools.md#состав-комнаты-botroom). Полностью обновить состав
можно вызовом `await self.refresh_room()`.

## `wait_for` ждёт до таймаута и ничего не получает

- Нужное событие должно приходить боту. Чат доставляется всегда, а для остальных
  событий переопределите их обработчик (достаточно пустого).
- Проверка `check` должна возвращать `True` для нужного события; проверьте условие.
- Всегда задавайте `timeout`. См. [«Диалоги»](commands.md#диалоги-wait_for).

## Бот «замирает», пока ждёт ответа игрока

Обработчики выполняются по одному, и ждущая команда занимает очередь. Это сделано
намеренно (так в коде не нужны блокировки). Для диалогов с несколькими игроками одновременно
запускайте диалог отдельной задачей: рецепт — в
[«Диалоги с несколькими игроками»](commands.md#диалоги-с-несколькими-игроками-одновременно).

## Можно ли использовать `requests`, `time.sleep` и другие блокирующие вызовы?

Нет. Блокирующий вызов останавливает весь цикл событий, и бот перестаёт читать сокет.
Используйте `await asyncio.sleep(...)`, `bot.http` (aiohttp) или
`await asyncio.to_thread(функция)` для тяжёлой синхронной работы.

## Сколько ботов можно создать и держать в комнате?

До **трёх активных ботов на аккаунт** и до **трёх ботов одновременно в одной комнате**. Кроме
того, существует общий лимит выданных ключей на аккаунт (кабинет сообщит, если он
исчерпан). Для создания и работы бота у владельца должна быть активная подписка PREMIUM.

## Что будет, если закончится PREMIUM?

Ключ не удаляется. Бот не сможет подключиться, пока подписка не будет продлена, а уже
подключённый бот при следующем подключении получит временный отказ. SDK повторяет попытки
сам, поэтому после продления бот вернётся без вашего участия.

## Как получить золото, которое заработал бот?

Бот получает чаевые золотом на свой кошелёк (`await self.api.gold()`). Владелец
забирает накопленное себе в личном кабинете: на карточке бота кнопка **«Забрать золото»**.
Бот может и сам тратить своё золото: `api.tip(...)` и `api.buy_item(...)`.

## Почему бот не пишет первым в личные сообщения?

Так задумано: бот **отвечает** в диалогах, где он уже есть, а начинает разговор человек.
`send_bulk_message` тоже пишет только тем, кто уже писал боту.

## Работает ли бот в 3D-комнатах?

Частично. В 3D доступны чат, шёпот, ходьба (`move_to`), список людей, личные сообщения,
кошелёк, гардероб, наряд и покупки. Эмоции, реакции, посадка, телепорт, модерация и
чаевые в 3D отказывают с `ResponseError`. Сводка — в [«Справочнике действий»](api.md#сводка).
Если сервер не поддерживает 3D для ботов, подключение отклоняется с понятным текстом.

## Можно ли запустить нескольких ботов в одном процессе?

Да: у каждого объекта `Bot` свой движок и своё соединение.

```python
import asyncio

from sukarisebot import Bot


class First(Bot):
    pass


class Second(Bot):
    pass


async def main() -> None:
    await asyncio.gather(
        First().run(token="srbot_1...", room_id="room-1..."),
        Second().run(token="srbot_2...", room_id="room-2..."),
    )


asyncio.run(main())
```

Если один из ботов завершится ошибкой, `gather` пробросит её; чтобы остальные продолжали
работать, оберните каждый запуск в свой `try/except` или используйте
`return_exceptions=True`.

## Как держать бота запущенным на сервере?

Запустите скрипт как системную службу, чтобы он стартовал после перезагрузки и
перезапускался при сбое. Пример для Linux (`/etc/systemd/system/sukarisebot.service`):

```ini
[Unit]
Description=SukaRise bot
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/opt/mybot
EnvironmentFile=/etc/mybot.env
ExecStart=/opt/mybot/.venv/bin/python -m sukarisebot mybot:MyBot
Restart=on-failure
RestartSec=5
User=mybot

[Install]
WantedBy=multi-user.target
```

В `/etc/mybot.env` лежат `SUKARISEBOT_TOKEN=…` и `SUKARISEBOT_ROOM_ID=…`; права на файл —
только для пользователя службы. SDK сам переподключается при обрывах связи, а
`Restart=on-failure` перезапустит процесс после неожиданного завершения.

## Как заменить токен?

В кабинете нажмите **«Новый токен»** на карточке бота: старый токен перестанет работать сразу.
Подставьте новый и перезапустите бота. Работающий бот со старым токеном при следующем
подключении получит отказ «invalid or revoked bot token».

## Почему тексты отказов сервера английские?

Протокол совместим с официальным SDK Highrise, а шлюз присылает тексты отказов на английском.
Переводы типичных отказов — в [«Ошибках и отказах»](errors.md#отказы-отдельных-запросов-responseerror).
Тексты исключений самого SDK и фразы бота по умолчанию — русские; фразы бота можно
заменить через [`Phrases`](commands.md#что-бот-говорит-сам-phrases).

## Как остановить бота?

Из консоли — `Ctrl+C`. Из кода — `await self.stop()` (например, в команде для
владельца); `run()`/`start()` после этого вернутся.

## Где посмотреть, что бот отправил и получил?

Работающий бот не пишет в журнал каждый запрос и событие, чтобы не засорять его.
`DEBUG` показывает только пропущенные кадры неизвестных видов. Чтобы увидеть все запросы
бота, запустите его в [`Harness`](testing.md): он записывает каждое действие в
`harness.requester.sent`. Для боевого подключения добавьте журналирование в свои
обработчики.
